# 升级说明

## 数据库升级

首次启动先用平台只读 SQLite probe 检查 active pointer。Zero v3 和 Zerox
v3 都先复制到隔离的 `watermelon_v4`，再做行数、金额、ID、关系、索引、
integrity 和 reopen 校验；校验成功后才切换 pointer。源数据库和 WAL/SHM
备份必须保持不变。未知、未来、损坏、锁定或 marker 不匹配的数据库会停
在 BootGate 恢复界面，不能当作新安装重置。

进程在复制中退出时，下一次启动只会处理拥有匹配 durable checkpoint 的
target：`writing` 丢弃后重建，`verified` 重新只读验证后复用。Watermelon
批写与 MMKV checkpoint 不属于跨存储原子事务，稳定记录 ID 和重试用于避免
重复入账。

## 导入导出

当前 JSON export version 为 v5，包含 incomes、category `kind`、`parentName`、
budgets、description 和 soft-delete 状态；历史 v0–v4 upgrader 保留。恢复
前会验证 JSON、引用和分类复合键，收入/支出同名分类不会互相覆盖。

## 回滚

发布前保留上一个 signed artifact 和迁移诊断日志。若候选启动失败：

1. 保留 legacy pointer 和源库文件，不删除 `watermelon.db` 或备份。
2. 从 Diagnostics 导出错误记录；不要手工删除 target marker。
3. 回滚应用版本后保持旧 schema pointer，或在修复版本中依据 checkpoint
   继续 reconcile；任何人工 reset 都必须先取得完整备份。

版本号、签名证书和商店升级策略尚未在本机完成，发布前必须补齐并记录在
`docs/RELEASE_QA.md`。
