## 目标架构和合并原则

Zero 作为长期维护和质量基线，保留预算、adaptive daily budget、CSV/JSON 导入导出、Zod 校验、诊断页、错误恢复、WCAG 颜色、FlashList、SwipeableRow/撤销、DonutChart、债务和本地优先边界。Zerox 只移植经过审查的中文、收入、二级分类、主题色和 AI 能力，不整支覆盖根目录。

第一阶段保留 `expenses` 与 `incomes` 两张表，在 repository/use-case 输出统一的 `TransactionRecord`。不直接重写为全新的 `transactions` 表，避免同时改变旧 ID、关系、导入导出和所有查询。

所有数据库工作都遵循：只读预检 → 备份 → 新库复制 → 行数/金额/关系/索引/重新打开校验 → 原子切换 pointer。未知 schema、空但已存在文件、未来版本、损坏、锁定和混合结构全部阻塞，不能回退成 fresh。

新安装路径在 P0 中明确为直接创建 v4 target 并写入 verified pointer；`decideDatabasePreflight` 已返回 `fresh-target`，不能让首装先落到没有收入/二级分类的 v3。

## 7 个工作包与 43 个原子任务

### P0：原生数据库安全底座（8 个任务，最高优先级）

1. Android 增加只读 SQLite metadata bridge，复用 WatermelonDB 的 dbName→path 规则，使用 READONLY 连接。
2. iOS 增加同等只读 bridge，区分 missing、permission、locked、corrupt。
3. 定义 JS probe contract，返回 `user_version`、表/列/索引、完整性结果和文件存在性。
4. 为 missing、version 0、future、混合 schema、损坏、WAL 建立双端 fixture 和 hash/mtime 不变断言。

Android 只读 metadata bridge 已实现并通过 debug APK 编译；没有连接设备，WAL/损坏/权限 fixture 尚未真机执行，iOS bridge 仍待 macOS/Xcode。

同一 Android bridge 已增加 readSnapshot 行读取契约，JS 端校验 8 张表和 row id；真实 source snapshot/copy 仍待接线。

Android source snapshot 现在会省略 legacy 文件中不存在的表（Zero v3 缺 incomes、Zerox v3 缺 budgets），JS 边界允许缺表但仍拒绝未知表和无效 row id；target read-back 继续要求 8 张表完整。此前无条件 `SELECT` 缺表会让 Zero v3 在复制前失败，已修复并通过 Java 编译和定向测试。

`createAndroidCopyDriver` 已完成组合边界，但 target freshness、backup/discard 策略和状态机接线仍由上层负责。

Android release 已完成原生编译、Hermes bundle 和 lint，因当前主机没有签名 keystore 在 packageRelease 停止；真机、签名和 iOS 仍未验收。

v4 target 模型、Income 和隔离 `createTargetDatabase` 工厂已准备完成；生产 v3 database.ts 未改变，避免提前打开 v4 adapter。

source-specific `normalizeLegacyRows` 也已落地，Zero/Zerox 的默认字段和 fail-closed 分类 kind 策略已固定；真实 SQLite copy 尚未接入。

注入式 `copyLegacyRows` driver 已完成备份→source snapshot→单个原子 target transaction（写入/回读/校验/commit 或 rollback）契约；真实 Watermelon writer 和 BootGate 仍未接入。

dual-db 状态机已覆盖 activation/activated-marker 不确定性：失败时保持 `verified`，等待下一次启动 reconcile，不把可能已激活的目标误记为 failed。

`runDatabasePreflight` 已把 active pointer、readonly probe 和 decision 组合为可注入 runner；target writer 和恢复界面完成前不接入主启动。

隔离 v4 target writer 已基于 Watermelon `prepareCreateFromDirtyRaw` + 单次 batch 实现，保留 id/status/changed；回读失败会丢弃未激活 target，真实 native writer/设备验证仍待完成。

已增加 durable migration checkpoint 契约：MMKV 单键保存 generation、source fingerprint、backup descriptor、target attempt/status 和 target fingerprint；坏 marker、不同 attempt、缺少 verified fingerprint 均 fail-closed。`decideTargetRecovery` 只返回恢复动作，不触碰文件，因此尚未接入 BootGate，也没有把 JS `unsafeResetDatabase` 宣称为进程崩溃后的原子回滚。

数据库工厂现在按 active pointer 选择 v3/v4 schema、migrations 和 modelClasses；v4 pointer 会注册 Income/TargetUser/TargetCategory，不再用 legacy v3 model graph 打开 target。只完成选择契约，native readonly preflight 仍必须先于 adapter 构造，缺失或 stale target 尚未允许进入主启动。

预检 runner 现在会在 legacy 文件缺失时继续只读探测 `watermelon_v4`；只有 legacy 与 target 都缺失才返回 `fresh-target`。发现残留 target、target integrity 失败或 target probe 错误都会阻塞，等待 checkpoint marker 和文件生命周期恢复逻辑。

`copyLegacyRows` 现在返回按固定表/字段/row id 顺序生成的 16 位内容指纹，区分缺表与空表并拒绝非有限数字；它用于检测复制前后内容变化，不是密码学完整性哈希，真正的备份和 native reopen 校验仍必须保留。

本轮已先完成纯 JS `verifyCopiedRows` 契约：由 source-specific planner 生成 `expectedTarget`，再与实际 read-back rows 比较；要求 8 张目标表都存在，逐 ID 比较既有字段和 `_status/_changed`，校验金额、双侧外键、分类 kind、父子分类 cycle/cross-user；它仍不替代 native reopen/index/integrity 校验。

5. 创建真正的 target v4 adapter/writer，禁止生产 adapter 直接打开 legacy 文件。
6. 实现 Zero v3/Zerox v3 行复制、字段补齐、批量写入和来源报告。
7. 实现备份、金额/行数/外键/ID/索引/重新打开校验、原子 pointer 切换与 durable resume。
8. 把 preflight、copy、verify、activate 接入 BootGate；迁移未完成或失败时不挂载主导航。

退出条件：三条路径（fresh、Zero v3、Zerox v3）可恢复；任何未知库不 reset；源库文件和内容保持不变。

### P1：统一数据域与导入导出（7 个任务）

## 推荐提交顺序

建议形成约 24–26 个 Conventional Commits，提交前固定执行三类审查：

1. `build(native): close rn 0.87 native validation`
2. `feat(db): add readonly sqlite preflight bridge`
3. `feat(migration): copy and verify legacy databases`
4. `fix(boot): gate main navigation on migration recovery`
5. `feat(schema): add unified v4 models and snapshots`
6. `feat(data): add transaction repository and keyed caches`
7. `feat(export): publish export v5 and atomic importer`
8. `feat(domain): migrate income and hierarchical categories`
9. `feat(i18n): add zh-cn and locale parity`
10. `feat(ai): add validated parser and privacy controls`
11. `feat(ai): add idempotent queue recovery and undo`
12. `fix(entry): replace route swap with shared entry mode`
13. `feat(nav): add animated bottom tab bar`
14. `test(ui): add animation and accessibility matrix`
15. `build(native): verify hermes fabric and release artifacts`
16. `ci(migration): add upgrade and export matrix`
17. `ci(release): enforce production readiness gates`

一个提交只能改变一条可验证主线；native、数据库、业务和动画不能混成“大合并提交”。

## 当前不做的事情

- 不为 `braces` 编造 3.0.4 override；该高危公告来自 RN Metro/CLI 上游，等待正式修复版本。
- 不把 WatermelonDB `SQLiteAdapter` 当作只读 reader 接入 BootGate。
- 不直接把两表重写成全新 transactions 表。
- 不把 React 19.3 降回 19.2.3；peer 范围只是兼容声明，React 19.3 是用户批准的目标栈，仍需原生 smoke 证明。
- 不用关闭 ESLint 规则来消除 warning；样式 error 门禁已启用。
