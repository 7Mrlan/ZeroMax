## 目标一句话

在 Zero 官方维护线的稳定能力之上，采用用户指定的最新前端栈，完成 Zerox 的收入、二级分类、中文、主题和 AI 能力的重写式合并；建立可恢复的 Zero v3/Zerox v3→统一 v4 数据迁移；修复录入与底部导航闪屏；通过 Android 原生、性能、无障碍、CI 和发布门禁，形成可维护的发布候选版本。

“完成”只在所有阻断验收项通过后成立。代码继承比例、代码行数、依赖安装成功、Jest 通过或 Android 编译成功都不能单独宣称完成。

## 目标边界和六个独立口径

1. **Zero 基线继承**：预算、adaptive daily budget、CSV/JSON、诊断、WCAG 颜色、FlashList、Swipeable/撤销、DonutChart、债务、本地优先能力继续可用。这是已有基线，不重复计入新功能完成度。
2. **Zerox 新功能交付**：收入 CRUD/统计、二级分类、中文与英文 key parity、主题色、AI 自动记账、队列恢复和混合首页流水进入根目录生产代码。
3. **数据迁移安全**：fresh、Zero v3、Zerox v3 三条路径都能复制、验证、重启恢复和切换；未知库、空但存在的库、未来库、混合库、损坏库、WAL/锁定库全部 fail-closed。
4. **交互和动画**：单路由 `AddEntryScreen`、`EntryMode`、无 `replace()` 闪屏、Reanimated 4.7 UI 线程动画、自定义 typed tab bar、reduce motion 和无障碍全部可验收。
5. **原生和性能**：Android 可安装、可启动、可签名发布；固定设备和固定 fixture 上完成 Zero/Zerox/候选三方 P50/P95 对照。没有实测不能写“更快”。
6. **发布和维护**：CI、审计、secret scan、E2E、身份、升级说明、隐私说明、CHANGELOG、SBOM/license attribution 和回滚路径齐全。

## 不变的技术决策

- 最终目标栈固定为：RN `0.87.1`、React `19.3.0`、TypeScript `7.0.2`、Reanimated `4.7.1`、Worklets `0.13.0`、React Navigation native `7.5.0`、bottom-tabs/native-stack `7.20.0`、Redux Toolkit `2.13.0`、FlashList `2.3.3`、WatermelonDB `0.28.0`、MMKV `4.3.2`、Zod `4.6.5`。
- 不回退到 React 19.2.3，不以兼容旧技术栈为完成条件；旧版本只可作为明确的对照构建。
- 保留 `expenses` 和 `incomes` 两张表，用 repository 输出统一的 `TransactionRecord`；不直接改成全新 `transactions` 表。
- 数据库路径固定遵循：只读 probe → backup → 新 v4 target → copy → read-back/金额/ID/关系/索引/integrity/reopen → 单次 pointer activation。Watermelon JS `batch` 提交后只能丢弃未激活 target，不能称作跨数据库事务回滚。
- Android 是本轮本地主验证平台；用户后续自行验证 iOS。代码层保留 iOS 路径，但 iOS 设备/Pods 结果必须标记为“外部验收待完成”。仓库当前没有 `macos/`，React Native macOS 不是本仓库已完成的平台。
- `braces` 高危公告若仍存在，发布门禁保持阻断；不编造 override、不关闭 audit、不把 waiver 当修复。

## 依赖 DAG 和执行规则

固定依赖关系如下，但不把它当成僵化 phase。每个新提交前都重新计算 DAG：

```text
native probe + artifact lifecycle + backup
              ↓
preflight-before-adapter + BootGate + durable migration
              ↓
v4 schema + TransactionRecord + import/export v5
              ↓
income/category/i18n/theme + Zero regression
              ↓
AI parser/privacy/idempotent queue
              ↓
AddEntry + cache/query fixes + flat FlashList
              ↓

              ↓
```

每一步严格执行：

2. 先做 adversarial review、代码质量 review、注释 review，明确会改变的契约和回滚点。
3. 只修改一条主线；数据库、native、业务和动画不得混成一个提交。

5. 将证据、失败、外部阻断和依赖影响写入文档。

## 阻断验收

### P0 数据迁移和启动安全

- native probe 在构造任何 Watermelon adapter 前运行。
- fresh、Zero v3、Zerox v3、unknown、future、empty-existing、corrupt、locked、permission、WAL/orphan fixture 全部有正负测试。
- source 的 bytes、mtime、内容 fingerprint 前后不变；backup 能 reopen、integrity check、恢复。
- 目标库必须验证 user_version、8 张表、精确列、索引、外键、行数、金额、ID、`_status/_changed` 和关系。
- 进程在 backup/copy/read-back/verified/activate 任一点被杀后，下一次启动不重复入账、不 reset 未知库、不丢源库；pointer 只切换一次。
- `active pointer=target`、`active pointer=legacy + verified target`、marker 缺失、attempt 不匹配、fingerprint 不匹配都要有 reconcile 结果。
- BootGate 未成功前不挂载主导航；失败页面可重试但不静默吞错。

### P1 数据域和导入导出

- Zero v3 和 Zerox v3 均能迁移到 v4；`description`、`budgets`、`incomes`、`parent_id`、`kind` 不丢失。
- `TransactionRecord` 统一金额、日期、kind、分类和来源，query key 至少包含 `userId + yearMonth + kind`，requestId 防止旧请求覆盖新月份。
- export v5 round-trip 100% 通过；历史 v0→v4 upgrader、CSV、soft-delete、undo、预算边界和重复分类通过。
- 分类复合键必须包含 `kind + parentId/parentName + name`，收入/支出同名不能覆盖。

### P2 Zerox 功能和本地化

- Income CRUD/统计/首页混合流水、二级分类、软删除/撤销、主题色和中文默认分类在新装/Zero/Zerox 三路 fixture 通过。
- `zh-CN` 与 `en` key parity；无用户可见硬编码中文；语言、日期、数字、货币联动。
- 保留 Zero 的预算、CSV/JSON、诊断、WCAG、FlashList、DonutChart、撤销和无障碍能力。

### P3 AI 安全和一致性

- 默认关闭网络能力；API key 只在本地安全存储，不进入 Redux、数据库、日志、导出、source bundle 或 crash report。
- 只允许 HTTPS 和 host allowlist；AbortController、timeout、响应大小上限、受控重试/退避、取消和脱敏日志齐全。
- parser 是纯函数，Zod 校验 response；支持相对日期、多条拆分、收入类型和分类 fallback。
- idempotency key 保证同一任务重复执行不重复入账；Watermelon 写入与 MMKV 任务状态不是跨存储原子事务，故以稳定记录 ID、写后重试和已存在检查形成可恢复提交边界；重启、失败详情、重试、批量撤销都有测试。
- secret scan、APK/bundle key scan 为 0 findings。

### P4 交互和动画

- `AddEntryScreen` 单路由 + typed `EntryMode`；不得用 `replace()` 切换录入模式。
- 快速切换 30/60 次不白屏、不丢表单状态、不重复查询；错误、键盘、Safe Area、深色和后台恢复通过。
- Reanimated 4.7/Worklets 0.13 的 indicator、crossfade、custom tab active pill 在 UI thread；动画可通过 reduce motion 关闭。
- RTL、TalkBack/VoiceOver、字体放大、重复点击和低端 Android 通过。
- 现有 Swipeable、ActionSheet、列表和图表动画逐项审计；不能只实现底栏后宣称全局流畅。

### P5 原生和性能

- Android API 35/36、debug/release、Hermes/Fabric、16 KB page、edge-to-edge、Safe Area、权限、backup/restore、R8 和签名 AAB/APK 均有证据。
- iOS 代码和 Podfile 变更保持 RN 0.87.1 目标；用户后续在 macOS/Xcode 自验，本机不把未运行结果标为通过。
- 固定 Android 设备、release Hermes/Fabric、100/1,000/10,000 行 fixture、1/100 天分布，对 Zero `d7725cd`、Zerox `a21abd6`、候选分别测：cold start/TTI、BootGate copy throughput、query P50/P95、tab/entry switch frame time/jank、长列表 dropped frames、JS/UI FPS、峰值 RSS/heap、AI latency。
- 输出原始 JSON、采集脚本、设备/build 信息和报告。没有实测禁止使用“快 X%”。候选 P95 不得较 Zero baseline 退化超过 5%；性能提升只有在同输入、同设备、重复实验达到统计显著后才能声明。

### P6 CI、发布和维护

- CI 增加 audit、secret scan、schema snapshot、migration matrix、export round-trip、Android artifact/install 和 E2E。
- 当前 format check 只检查变更文件，必须与全库 baseline exception 分开报告。
