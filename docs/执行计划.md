# Zero × Zerox 分步执行计划与审查记录

本文件记录实际执行顺序。每个大步骤必须形成一个可回滚的 Conventional Commit；提交前必须完成三类审查并记录结果：

1. **对抗性审查**：主动寻找数据丢失、重复写入、竞态、旧设备升级失败、隐私泄漏、无障碍回归和性能退化。
2. **代码质量审查**：类型、边界、错误处理、依赖方向、重复逻辑、测试覆盖和可维护性。
3. **注释审查**：注释只解释原因、兼容性约束和迁移规则；删除过时、重复或会误导未来维护者的注释。

## Phase 0：Fork 与基线冻结

目标：在根目录建立可构建的 Zero 官方基线，并保留两个上游同步入口。

步骤：

1. 创建 `codex/zero-zerox` 分支。
2. 添加 `zero-upstream` 和 `zerox-upstream` 远端。
3. 将 Zero v2.6.6 完整源码放入根目录，保留许可证、原生工程和测试。
4. 记录 Node、包管理器、RN、原生 SDK 和锁文件现状；当前根提交父级是 Zero `d7725cd`。
5. 拉取并记录 `zerox-upstream/v1.0.0`，记录三类审查结果；CI/提交规范改造留给 Phase 1。

审查重点：

- 根目录源码是否确实来自 `d7725cd`，没有混入 Zerox 代码。
- Android/iOS 工程、Hermes、新架构、WatermelonDB JSI 和测试文件是否完整。
- 是否保留 BSD 2-Clause LICENSE、上游 attribution 和回滚路径。
- 根目录是否只保留 Zero 基线实际使用的 Bun workflow/lock；pnpm 切换留给 Phase 1，不能在本提交半切。
- 当前环境缺 Bun 1.3.14、Java/Android SDK、Xcode/Pods，typecheck/lint/Jest/native smoke 只能记录为环境阻断，不能宣称通过。

提交格式：`build(baseline): fork zero v2.6.6 into workspace`

## Phase 1：工程规范与可观测启动

目标：先建立质量门禁，再处理业务合并。

步骤：

1. 统一包管理器和 lockfile。
2. 加入 commitlint、Commitizen、Husky/lint-staged、CODEOWNERS、PR 模板。
3. 加入 lint、format、typecheck、unit test、migration test CI。
4. 引入 `BootGate`，串行等待数据库/数据迁移和 AI 队列恢复。
5. 保留生产可诊断错误，不使用 `LogBox.ignoreAllLogs()` 掩盖问题。

审查重点：命令在干净环境可复现；失败会阻止发布；错误不会包含 API Key/账本内容；注释与真实启动顺序一致。

提交格式：`ci(tooling): add reproducible quality gates`

## Phase 2：官方能力回迁

目标：把 Zero v2.6.6 的预算、导入导出、CSV、诊断、性能和无障碍实现带入主线。

步骤：按 backend → database service → Redux → screen 的顺序逐层移植；每层独立测试。

审查重点：导入原子性、导出兼容、预算金额边界、FlashList 回收、撤销删除、VoiceOver/TalkBack。

提交格式：`feat(core): restore zero v2.6.6 data and performance features`

## Phase 3：Zerox 领域能力

目标：加入收入、二级分类、中文 i18n、主题色和 AI 记账，同时保持 Zero 数据能力。

步骤：

1. 设计 schema v4 双路径迁移和 export v5。
2. 保留 `expenses`/`incomes` 两表，以 repository 输出统一 `TransactionRecord`。
3. 迁移收入、`parent_id/kind`、默认分类和中英文旧数据。
4. 迁移 AI parser/queue/recovery，并加入幂等键、超时、Zod runtime 校验和隐私开关。

审查重点：Zero v3→v4、Zerox v3→v4、新安装三条路径；同名收入/支出分类；AI 重启重复入账；云端网络权限和密钥泄露。

提交格式：`feat(domain): add income categories and resilient ai bookkeeping`

## Phase 4：交互与动画

目标：消除录入闪屏，加入丝滑底部导航。

步骤：

1. 新增单路由 `AddEntryScreen` 和显式 `EntryMode`。
2. 支出/收入表单共享输入状态和提交 use-case。
3. Reanimated shared value 驱动分段 indicator 和表单 crossfade。
4. 自定义 typed tab bar，保持 Tab screen mounted，加入 reduce motion。

审查重点：快速来回切换 30 次、键盘、Safe Area、深色模式、低端 Android、StrictMode 重挂载、屏幕阅读器焦点。

提交格式：`fix(ux): remove entry switch flicker and animate tabs`

## Phase 5：RN/依赖升级

目标：在业务稳定后升级 RN 0.87.1 工具链。

顺序：原生工程 → RN/React peer → Babel/Metro/Jest → Reanimated/Worklets → Navigation/Gesture/Screens → FlashList → MMKV/Nitro → Zod/RTK → TS7 工具链。

审查重点：Android API 35/36、iOS/Xcode、Hermes/Fabric、16KB page、WatermelonDB JSI、legacy decorators、`InteractionManager` 替换、Reanimated ref/layout 行为。

提交格式：`build(deps): upgrade react native toolchain`

## Phase 6：发布验收

必须通过：

- 新安装、Zero v3→v4、Zerox v3→v4 数据迁移。
- export v0/v4→v5、round-trip、损坏文件和恢复失败测试。
- Android/iOS debug 与 release smoke。
- 录入切换、底栏切换、长账单列表、AI 队列恢复 E2E。
- lint、format、typecheck、unit、migration、依赖审计和 secret scan。

提交格式：`ci(release): verify migration and production readiness`
