### 迁移预检决策（本轮）

- 新增 `decideDatabasePreflight` 纯决策层：只有真正缺失的 legacy 文件允许 `fresh-target`；Zero/Zerox v3 必须进入 copy；精确 v4 只能在 target pointer 下打开；存在但为空、未来版本、混合 schema、损坏、锁定和 pointer mismatch 全部 blocked。v4 检测改为精确 `version === 4`，不会把 v5 当作可用目标。
- 该决策层尚未接入 `BootGate`，因为 WatermelonDB 0.28 的 `SQLiteAdapter` 没有只读初始化选项，现有 `watermelonLegacyReader` 仍可能在构造时创建 WAL、执行迁移或 reset；在原生 bridge 完成前不允许把它接入生产启动。
- 下一步必须在 Android/iOS 原生共享 Watermelon 路径解析逻辑，使用 READONLY SQLite connection 实现 metadata probe，并覆盖 missing、version 0、future version、损坏和 WAL fixture；probe 通过后才能重排 `backend/index.ts` 的启动顺序。
- 本轮先新增 `nativePreflight.ts` JS/native contract：Zod 校验 `missing/ready`、版本、表/列、索引和 integrity；bridge 不存在、输出非法或调用失败一律 blocked。
- Android `ZeroReadOnlySqlite` bridge 已实现并通过 RN 0.87.1 debug APK 编译；它复用 WatermelonDB 路径、使用 `OPEN_READONLY`、不创建文件，当前无 Android 设备，iOS bridge 仍待 macOS/Xcode。
- Android debug APK 已生成；release 任务已完成 native compile、Hermes bundle、lint 和资源处理，最终仅因没有正式 `keystore.properties` 在 `packageRelease` 停止。根 devDependency 已固定 `hermes-compiler@250829098.0.17`，解决 pnpm release bundle 的 hermesc 路径缺失。
- 随后新增 `verifyCopiedRows` 纯验证契约：source-specific planner 先生成 `expectedTarget`，再与实际 read-back rows 比较；8 张目标表必须显式存在，逐 ID 比较既有字段和 `_status/_changed`，校验金额、双侧外键、分类 kind 与父子分类环；它不替代 native reopen/index/integrity 校验。
- v4 target 模型和 `createTargetDatabase` 工厂已独立落地，包含 Income、父子分类和用户收入关联，但尚未接入生产 `database.ts`；只有 native probe/copy/verify 完成后才能打开它。
